# ADR 0005. 좁은 화면 UX — 본문 밀어 탭 넘기기 · 로그아웃 확인 시트 · 위젯 모양 더하기

- 상태: 채택
- 날짜: 2026-11-19
- 관련: ADR 0004(셸 나누기)

## 1. 본문을 옆으로 밀어 탭 넘기기

`MobileApp` 의 `<main>` 에 `useSwipeTabs`(features/shell/hooks)를 단다. 왼쪽으로 밀면 다음 탭, 손을 따라 본문이 움직이고
놓으면 넘기거나(1/4 폭 · 최대 96px 넘게, 또는 0.5px/ms 넘게 튕기면) 제자리로 돌아온다. 넘긴 뒤 들어오는 움직임은 기존 `.page-in` 을 쓴다.
판정(`axisOf` · `resist` · `swipeStep`)은 DOM 없는 함수로 빼 `node --test` 로 확인한다.

**충돌 정리**

| 겹치는 것 | 처리 |
| --- | --- |
| 세로 스크롤 | touch 이벤트를 passive 로만 듣고, 처음 10px 에서 가로가 세로의 1.2배를 넘어야 가로로 본다 |
| 안쪽 가로 스크롤 칸 | 시작점 위로 `overflow-x: auto/scroll` 이면서 넘치는 칸, 또는 `data-no-swipe` 가 있으면 넘기지 않는다 |
| 위젯 편집(길게 눌러 드래그) | 편집 중에는 끈다 |
| iOS · 안드로이드 뒤로 제스처 | 화면 끝 24px 에서 시작한 밀기는 브라우저 몫 |
| 열린 창(dialog) | 넘기지 않는다 |

**검토한 다른 길**

- `@use-gesture/react` — `axis: 'lock'` · swipe 판정(거리 · 속도 · 시간)이 있어 편하다. 대신 공식 문서가 권하는 대로
  `touch-action: pan-y` 를 걸어야 하는데, main 에 걸면 안쪽 가로 스크롤 칸까지 막힌다(touch-action 은 조상과 교집합). 판정 자체는
  40줄이라 의존성을 더할 만큼은 아니라고 봤다. 핀치 · 관성 같은 제스처가 늘면 다시 본다.
- `react-swipeable` — 가볍지만 따라 움직이는 표시 · 가로 스크롤 칸 제외를 결국 직접 짜야 한다.
- 탭을 가로 캐러셀(CSS scroll-snap)로 — 네 화면을 늘 그려 둬야 하고, 화면마다 세로 스크롤 위치가 섞인다. 화면 lazy 로딩도 깨진다.

참고: [use-gesture 옵션(axis · touch-action)](https://use-gesture.netlify.app/docs/options)

## 2. 로그아웃 확인 시트

사용자 메뉴 · 설정 화면의 로그아웃은 바로 `LOGOUT_URL` 로 가지 않고 `LogoutConfirm` 을 연다. 휴대폰은 아래에서 올라오는 시트,
넓은 화면은 작은 창이다. 새 컴포넌트를 들이지 않고 기존 `Modal`(네이티브 `<dialog>` · 끌어 내려 닫기 · 뒤로 가기로 닫기)에
`compact` 를 더했다 — 시트가 85% 고정 높이 대신 내용 높이만큼만 올라온다.

- **왜 확인을 넣나**: SSO 세션까지 끊어 다른 사내 서비스도 함께 로그아웃된다. 메뉴 끝 항목이라 잘못 누르기 쉽다.
- **비용**: 한 번 더 눌러야 한다. 되돌릴 수 없는(다시 로그인해야 하는) 일이라 받아들인다.
- `vaul` 같은 시트 라이브러리는 검토만 — 지금 Modal 이 이미 시트 동작(끌기 · 초점 가두기 · 뒤로 가기)을 갖고 있어 두 벌이 된다.

## 3. 위젯 모양 더하기

좁은 화면 4칸 격자에 **반 줄 2×1**(아이콘 · 제목 · 숫자)과 **기둥 2×4**(작게 2×2 모양을 세로로 늘림)를 더했다.
`@dvi/core/widget` 의 `StackSize` · `MiniSize` 에 넣어 웹과 앞으로의 앱(apps/mobile)이 같은 이름을 쓴다.

- 2×1 은 `MiniPanel` 의 띠 모양을 반 폭으로 — 요약 줄은 빼고 버튼 이름(aria-label)에 담는다. 빠른 링크 · 업무시스템은 두 개를 나란히.
- 2×4 는 `lookOf` 로 2×2 모양을 쓴다 — 위젯마다 새 모양을 그리지 않아 코드는 거의 늘지 않는다. 대신 늘어난 칸은 여백이 많을 수 있다.
- 저장된 배치(`parseStack`)는 이름 목록으로 거르므로, 옛 버전은 새 이름을 모르는 크기로 보고 기본 크기로 돌아간다(데이터는 잃지 않음).
