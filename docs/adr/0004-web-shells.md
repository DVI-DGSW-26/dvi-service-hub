# ADR 0004. 웹은 App 을 실행점으로 두고, 넓은 화면 · 좁은 화면 셸과 위젯 판을 나눠 받는다

- 상태: 채택
- 날짜: 2026-11-19
- 관련: ADR 0002(기능 모듈), ADR 0003(모노레포)

## 맥락

`App.tsx` 하나가 사이드바(넓은 화면) · 탭 바(좁은 화면) · 편집 독 · 갤러리를 모두 그리고, 위젯 판(`WidgetGrid`)도 안에서
`area.lg` 로 react-grid-layout 칸 판과 4칸 격자(StackBoard)를 갈랐다. 그래서

- 휴대폰도 react-grid-layout · react-draggable · react-resizable 과 칸 판 코드를 받고 파싱했다.
- 좁은 화면에서도 페이지 넘김 휠 처리가 붙어 보이지 않는 `layout.page` 를 바꿀 수 있었다(판은 모든 페이지를 한 줄로 쌓는데).
- 한 파일에 두 화면의 조건(`board ? … : …`)이 섞여 읽기 어려웠다.

## 결정

```
app/
  App.tsx         실행점 — useHub() 로 공용 상태를 들고, 64rem 으로 셸을 고른다(lazy)
  useHub.ts       라우트 · 로그인 사용자 · 검색어 · 즐겨찾기 · 꾸미기 · 위젯 배치 · 편집 중 — 두 셸이 같이 쓴다
  DesktopApp.tsx  사이드바 · 갤러리(목업) · 편집 독 · 칸 위젯 판(DesktopBoard)
  MobileApp.tsx   탭 바 · 편집 탭 바 · 빈 곳 눌러 편집 끝내기 · 4칸 위젯 판(MobileBoard)
  Screens.tsx     본문 화면(홈 자리는 셸이 넣는다)
features/home/components/
  DesktopBoard    react-grid-layout 칸 판 · 페이지 넘김 · 기준선
  MobileBoard     StackBoard(4칸 격자) · 폭 재기
  HomePage        부서 안내 · 편집 안내 + children(셸이 고른 판)
```

- 상태는 App 이 든다 — 창 폭을 바꾸거나 태블릿을 돌려 셸이 갈려도 검색어 · 편집 중 · 배치가 이어진다.
- `HomePage` 는 판을 `children` 으로 받는다. 판을 prop 이름으로 고르면 두 판이 한 모듈에 정적으로 묶여 같은 청크에 들어간다.
- 편집 되돌리기 키(Ctrl+Z · Y)는 `useUndoKeys` 로 빼 두 판이 같이 쓴다. 페이지 넘김(`usePageNav`)은 넓은 화면 전용이 됐다.

## 트레이드오프

- **처음 방문은 한 번 더 왕복한다.** 진입 번들을 실행한 뒤에 셸 청크를 부른다. 서비스 워커(`public/sw.js`)가 `/assets/*` 를
  캐시 우선으로 받아 두므로 두 번째부터는 네트워크를 타지 않는다. 사내 포털이라 재방문이 대부분이다.
- **받는 양**(빌드 기준): 이전 처음 로드 664kB → 공통 504kB + 좁은 화면 셸 73kB(≈577kB, -13%) / 넓은 화면 셸 150kB(≈654kB).
  휴대폰은 칸 판 라이브러리를 아예 받지 않는다.
- 두 셸에 TopBar · main · 배경 그림 같은 뼈대가 비슷하게 두 번 적힌다. 화면마다 달라지는 조건(여백 · 편집 막대 · 빈 곳 누르기)이
  더 많아 한 컴포넌트에 플래그로 묶는 것보다 읽기 쉽다고 봤다. 공통이 더 늘면 `Screens` 처럼 조각으로 뺀다.
- 셸이 갈리는 순간(창 폭이 64rem 을 넘을 때) 셸 컴포넌트는 새로 마운트된다 — 사이드바 접힘 · 위젯 고르기 같은 셸 안 상태는 그 셸 몫이라 처음으로 돌아간다.

## 검토한 다른 길

- **두 셸을 정적으로 가져오기** — 왕복은 없지만 휴대폰도 칸 판 라이브러리를 받는다. 코드 정리 효과만 남는다.
- **CSS(lg:hidden)만으로 가르기(이전 방식)** — 코드가 하나지만 받는 양 · 조건 섞임이 그대로다.
- **위젯 판만 lazy 로** — 셸 조건 섞임이 남는다. 셸 단위로 나누면 사이드바 · 갤러리 · 편집 독도 같이 빠진다.
